Abstract

Summary of the Work

Real drivers routinely deviate from shortest/fastest routes due to unwritten preferences: comfort over familiar roads, aversion to sharp turns, preference for wide arterials. These preferences cannot be read off a map but are embedded in observed driving patterns.

This project applies Maximum Entropy Inverse Reinforcement Learning (MaxEnt IRL) to recover hidden driver reward functions from expert GPS trajectories. We model route choice as an MDP on a directed OSM road graph, with a reward that is a linear combination of 11 interpretable features (road class, length, turn type, goal direction, edge familiarity).

We resolve the IRL ambiguity via the maximum-entropy principle, solving for reward weights with exact gradient computation and L-BFGS optimisation. On 3,000 real Porto taxi trips (600 held-out test trips), the final model reaches Edge F1 = 0.682 (95% CI 0.657–0.708) vs 0.636 for Dijkstra-Shortest, with 93.7% Top-1 junction accuracy. In 5-fold CV the F1 is 0.669 ± 0.010 vs 0.630 ± 0.003.

Introduction

Problem Motivation & Research Gap

Why Routes Matter

  • Navigation apps offer shortest or fastest routes — real drivers routinely ignore both.
  • Real choices encode implicit preferences: road familiarity, turn comfort, lane width, road class.
  • These preferences are unobservable directly — drivers cannot articulate their own rules.
  • Recovering them enables personalised navigation, realistic traffic simulation, and AV behaviour design.

Research Gap

  • Shortest/fastest path: Single-metric; ignores driver comfort entirely.
  • Discrete choice models: Require strong parametric assumptions; no sequential planning.
  • Myopic classifiers: Junction-level only; no destination awareness; loops and inflates path length 1.78×.
  • Sampling-based / deep IRL: Often approximate expected feature counts or give up interpretable weights.

Objective

Given D = {τ₁,…,τₙ} on graph G, find
w* = argmaxw Σᵢ log P(τᵢ | w, oᵢ, dᵢ) − λ‖w‖²
// maximum likelihood of observed routes under MaxEnt policy

What Inverse RL Is

Forward RL: Reward R → Policy π (standard RL)
Inverse RL: Demonstrations D → Reward R (our task)
w* = argmax P(D | w) · P(w)
// find weights making observed routes most likely

Problem Formulation

Mathematical Formulation

Task Definition

Given directed road graph G = (V, E) from OpenStreetMap and N expert demonstrations D = {τ₁,…,τₙ}, each τ = (e₀, e₁,…, eₖ) is a road-segment sequence from origin o to destination d.

Objective:
w* = argmaxw Σᵢ log P(τᵢ|w,oᵢ,dᵢ) − λ‖w‖²
// max-likelihood of demonstrations under MaxEnt policy
Reward Function: R(s,a) = wᵀφ(s,a)
// linear reward over 11-dim features (v3)
MaxEnt Policy: π(a|s) ∝ exp(Qsoft(s,a))
// Boltzmann / softmax over action values
Gradient (exact): ∇wNLL = Eπ[φ] − φexpert + λw
// feature expectation matching + L2 penalty

Constraints & Assumptions

  • Linear Reward: R = wᵀφ — interpretable but limited to linearly separable preferences.
  • Markov Property: s = incoming directed edge (fixes node and heading) — turn geometry fully determined; destination d is a fixed episode parameter.
  • Maximum Entropy: Among all policies matching expert feature expectations, choose max-entropy one — models stochastic drivers naturally.
  • Full Observability: HMM map-matched edge sequences are treated as ground truth (matching errors ignored).
  • Finite Horizon, γ = 1: Episodes end at the destination; H = 80 keeps values finite even if a reward term is positive.

Problem Formulation — MDP

MDP: From the Course Grid-World to a Road Network

Course example: 3×4 grid, terminals +2 / −2

From the course notes (MDP-pdf): 0.6 intended move, 0.2 slip to each side, bump into a wall → stay, step reward −0.5, solved by value iteration.

Our MDP — formal definition

M = ⟨S, A, P, R, γ⟩ with fixed destination d
// fully observable, deterministic, goal-terminated; reward unknown
  • S = E ∪ {GOAL, DEAD}: incoming directed edges (6,784); GOAL = {e : head(e) = d}; DEAD = edges with no out-edge.
  • A(e) = {e′ : tail(e′) = head(e)} — roads leaving the junction (2–4).
  • P(e′ | e, a=e′) = 1 — choosing a road is arriving on it.
  • R(e,e′) = wᵀφ(e,e′), φ ∈ ℝ¹¹; w learned by MaxEnt IRL.
  • γ = 1, horizon H = 80; V(GOAL) = 0, V(DEAD) = −∞.
  • π(e′|e) = exp(Q − V), V(e) = log Σ exp[R + V(e′)].
The diagram below is a worked toy instance of exactly this MDP.

Worked example: a small road MDP (states = circles, actions = diamonds, terminals = double circles)

Green = positive terminal (destination reached). Red = negative terminal (dead end, never chosen). Because the dynamics are deterministic, every action→state arrow has P = 1.00; the randomness is the policy π on state→action arrows. Rewards are computed from the learned v3 weights for plausible edge features (e.g. A3: sharp turn −1.46, moving away from goal −0.30, step −0.67). Entering GOAL adds a +5 bonus, drawn so the positive terminal looks like the course examples; since every trip ends at GOAL exactly once, the bonus shifts all routes equally and the policy π is unchanged.

Proposed Methodology

Maximum Entropy IRL — Algorithm & Equations

Algorithm Pseudocode

1INPUT: demos D, graph G, horizon H=80, λ=0.001
2INIT: w ← 0 ∈ ℝ¹⁰
3── Pre-compute ──────────────────────────────
4φ_expert ← Σᵢ traj_features(τᵢ) // expert counts
5T_feat ← compute_transition_features(G) // turn φ
6── Objective (called by L-BFGS) ─────────────
7def NLL(w):
8 r_T ← T_feat @ w // transition rewards (vectorised)
9 for each destination d:
10 L ← soft_value_levels(w, d, H) // backward
11 for each τᵢ with dest=d:
12 logZ += expected_counts(w,L,oᵢ,d,acc_T,acc_0)
13 φ_π ← acc_T @ T_feat + acc_0 @ F_edge
14 NLL = -(w·φ_expert - logZ)/N + λ/2·‖w‖²
15 ∇ = -(φ_expert - φ_π)/N + λ·w
16 return NLL, ∇
17── Optimise ─────────────────────────────────
18w* ← L-BFGS-B(NLL, w₀=0, jac=True, maxiter=25)
19── Route generation ─────────────────────────
20V ← soft_value_iteration(w*) // converge
21route ← Viterbi_Dijkstra(origin, dest, w*)
22OUTPUT: w*, routes for all test OD pairs

Backward Pass: Soft Value Iteration

L[0][e] = 0   if   tail(e) = destination
L[k][e] = log Σe' exp(r(e,e') + L[k-1][e'])
       = logaddexp.reduceat(r_T + L[k-1][e_dst])
// finite-horizon: k = 1…H. No divergence guarantee.

Forward Pass: Expected Feature Counts

D[e₀] ← softmax(F_edge[e₀]·w + L[H-1][e₀])
For k = H-1…1:
  π(e→e') = exp(r(e,e') + L[k-1][e'] − L[k][e])
  m(e→e') = D(e) · π(e→e')
  D(e') = Σe m(e→e')
φ_π = acc_T @ T_feat + acc_0 @ F_edge
// exact, no Monte Carlo sampling

Route Generation: Viterbi–Dijkstra

cost(e→e') = max(0, V(e) − Q(e,e'))
route = argminpath Σ cost(transitions)
// Dijkstra on edge-states; O((E+T)log E) per query

Why Maximum Entropy?

MaxEnt resolves IRL ambiguity by choosing the policy of maximum entropy among all policies matching expert feature expectations. This naturally models stochastic, sub-optimal human behaviour without explicit noise assumptions, and uniquely specifies the posterior over demonstrations.

Performance Evaluation Metrics

RL-Specific & Problem-Specific Metrics

RL-General Metrics (Adapted for IRL)

Convergence Speed
NLL / trajectory vs L-BFGS iteration. Monitors how fast the reward function converges. On Porto the fold NLL/trip falls 13.3 → 5.57 and the gradient norm reaches ~0.05 within 20 iterations.
Sample Efficiency
F1 as a function of N demonstrations. Not yet measured on Porto — listed as future work.
Stability / Seed Sensitivity
L-BFGS is deterministic given demos, so variability comes from data splits. We report fold mean ± std over 5-fold CV (F1 ±0.010 for IRL-v3); multiple seeds are future work.
Trip NLL (IRL Proxy)
Negative log-likelihood of a whole held-out trip under the learned policy: 5.46 (v3) vs 6.12 (v1) — lower is better. There is no oracle on real data, so this replaces regret.
Generalisation Gap
All reported metrics are on held-out trips (never used for fitting or for choosing α). A formal train-vs-test log-likelihood gap is not reported.
Computational Efficiency
Training: ~13 min per fold on CPU (soft VI per destination). Parameters: 11 scalars. Memory: O(E·H) floats per destination. Practical at district scale.

Why These Metrics?

  • Edge F1: Canonical route overlap — combines precision (no spurious roads) and recall (no missed roads).
  • Edge Jaccard: Stricter than F1 — penalises both over- and under-prediction of road sets.
  • Path Length Ratio: Detects looping (ratio ≫ 1) or excessive shortcuts (ratio ≪ 1).
  • Top-k Accuracy: Junction-level; immune to error accumulation along routes.
  • Log-Likelihood: Probabilistic fit to unseen trajectory sequences.
  • Bootstrap CI + paired test: 95% per-trip CIs and paired p-values against Dijkstra-Shortest.

Discussion: Key Findings

  • Modest but significant gain: calibrated IRL-v3 beats Dijkstra-Shortest by +0.046 F1 (paired p = 2.7e-5); the raw model is only +0.023 (p = 0.06).
  • Honest negative result: with the original v1 features IRL was worse than Dijkstra-Shortest (0.611 vs 0.636, p = 0.029).
  • A popularity baseline ties us: Pop-Shortest (0.671) matches IRL-v3 in CV — much of our gain is the familiarity signal.
  • Strong local fit: 93.7% Top-1 and 99.9% Top-3 junction accuracy.
  • Myopic classifier fails globally: F1 0.162 and 1.78× path length without a destination-aware value function.

Why IRL Beats (or Doesn't Beat) Each Baseline

🎯
vs Dijkstra-Shortest
Real taxis mostly take short routes, so this is hard to beat. Calibrated IRL-v3 gains +0.046 F1 (p = 2.7e-5) by also penalising turns, moving away from the goal and unfamiliar edges. The original v1 features did not.
🌐
vs Myopic: global planning is essential
The myopic classifier has no destination-aware value function; its local decisions compound into detours (F1 0.162, 1.78× length). Soft value iteration is the critical ingredient.
⚖️
vs a popularity baseline
In 5-fold CV, Pop-Shortest (F1 0.671) matches IRL-v3 (0.669). IRL's advantage is a calibrated route distribution (trip NLL 5.5, Top-1 93.7%) with interpretable weights, not a higher F1.

Robustness / Sensitivity / Generalization & Limitations

Robustness Analysis & Known Limitations

What We Measured

🔁
Cross-validation stability
5-fold CV: IRL-v3 calibrated F1 = 0.669 ± 0.010 (fold std) vs Dijkstra-Shortest 0.630 ± 0.003. Single seed (0); seed variation not yet measured.
📏
Statistical significance
Per-trip bootstrap 95% CIs (n = 600) and paired tests vs Dijkstra-Shortest: v3 calibrated p = 2.7e-5; v3 raw p = 0.061; v1 p = 0.029 (IRL worse).
🚦
Trip-length effect
IRL and Shortest agree on 44% of trips; on short trips (9–26 edges) F1 is similar (Jaccard 0.659 vs 0.653) — diagnostics.json (v1).
⚠️
Collinear features
length vs travel_time (r = 0.81) and primary vs residential (r = −0.93) made v1 weights unidentifiable; v2/v3 fix this with reference levels.
🧪
Familiarity leakage control
Familiarity counts come from a separate pool of map-matched trips disjoint from train/val/test.

Known Limitations

⚠️ Linear Reward Assumption
R = wᵀφ cannot model feature interactions. A neural reward would help but loses interpretability.
⚠️ Single Reward for All Drivers
One w for every taxi and trip; no time-of-day or per-driver heterogeneity (a context-conditioned reward is prototyped in src/context_irl.py but not reported).
❌ Weak margin over simple baselines
Gain over Dijkstra-Shortest is +0.04–0.05 F1, and a popularity-weighted shortest path matches IRL in CV.
❌ Map-matching noise & small sample
Only 40% of attempted trips matched (3,000 of 7,528); matching errors are treated as ground truth. One city, central area only.
❌ Static network, scalability
No congestion or time-of-day in the state. Exact soft VI per destination takes ~13 min per fold at 6.8k edges; city scale needs approximation.

Conclusion and Future Work

Summary, Contributions & Future Directions

Main Findings

✅ Real-data IRL beats the strongest classical baseline, modestly
Edge F1 0.682 vs 0.636 for Dijkstra-Shortest on 600 held-out Porto trips (p = 2.7e-5); 0.669 vs 0.630 in 5-fold CV.
✅ Interpretable preferences
Sharp turns (−1.46), slight turns (−0.52), moving away from the goal (−0.29) are penalised; familiar edges are favoured (+0.87).
✅ Good local decision model
Top-1 junction accuracy 93.7%, Top-3 99.9%, trip NLL 5.46 (v1: 6.12).
⚠️ Caveats
The original features lost to Dijkstra; a popularity-weighted shortest path ties IRL in CV (0.671 vs 0.669); one seed, one city.

Future Work Directions

🧠
Deep MaxEnt IRL (Neural Reward)
Replace linear wᵀφ with CNN/GNN over road context. Captures non-linear and interaction-based preferences. Trades interpretability for expressiveness.
🔬
More Seeds & Sample Curves
Multiple seeds, horizon and training-size sweeps on Porto.
👥
Multi-Modal IRL (Driver Clusters)
Model heterogeneous drivers via mixture-of-IRL or Dirichlet-process IRL. Learn per-cluster weights: aggressive vs comfort-seeking vs eco drivers.
⚡
Scalable Approximate IRL
Extend to full-city graphs via hierarchical VI, GPU-accelerated sparse ops, or sampling-based expected counts. Target: full Porto and beyond.
🔄
Online Preference Adaptation
Update w* in real-time as new trips arrive — Bayesian IRL or streaming gradient descent for truly personalised, adaptive routing.
🚗
AV Behaviour Cloning
Use recovered reward as dense reward signal for RL-based autonomous vehicle training — avoids manual reward engineering for human-compatible driving.
